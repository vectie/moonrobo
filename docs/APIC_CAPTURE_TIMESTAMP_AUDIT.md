# APIC capture and Isaac Lab state timestamps

Static audit on 2026-10-24 against the locally pinned `target/isaaclab-source` tree. This checks whether four exported state views can stay current when the native runtime replays saved APIC graphs without Python. It does **not** establish replay numerical parity.

The producer's [`Scene::force_queries`](../src/learning_aligned/producer/sdk.mbt) calls `scene.update(dt)`, `_refresh_user_order_state()`, and then reads `root_link_pose_w`, `root_com_vel_w`, `joint_pos` and `joint_vel`. `dt` is `0.02` for `step` and `0` for `reset`, `context` and `refresh`. [`Scene::capture`](../src/learning_aligned/producer/sdk.mbt) runs each role body between `wp.capture_begin(apic=True)` and `capture_end`; the roles are captured in `step → reset → context → refresh` order in the [exporter](../src/learning_aligned/producer/export.mbt). The native [APIC runtime](../src/learning_aligned/native/aot_solver.cpp) only launches the saved graphs; it does not rerun `scene.update` or any Python getter.

In the pinned [ArticulationData implementation](../target/isaaclab-source/source/isaaclab_newton/isaaclab_newton/assets/articulation/articulation_data.py), `update(dt)` increments the Python `_sim_timestamp` and may update lazy acceleration buffers (around lines 149–159). [InteractiveScene.update](../target/isaaclab-source/source/isaaclab/isaaclab/scene/interactive_scene.py) forwards `dt` to each articulation (around lines 458–473); its default `lazy_sensor_update=True` is defined in `interactive_scene_cfg.py` around line 97. Those timestamp guards are not present on the four exported Tier-1 getters: `root_link_pose_w` and `root_com_vel_w` return pinned simulation-state `ProxyArray`s (around lines 645 and 702); `joint_pos` and `joint_vel` return pinned arrays (around lines 1110–1125). The root arrays bind directly to Newton state memory, while user-ordered joint shadows, if needed, are refreshed by explicit Warp gather/reorder launches (around lines 1579–1608 and 2101–2167). The fixed getters therefore do not require Python timestamp increments at replay time.

For `step`, the pinned [NewtonManager `_simulate_full`](../target/isaaclab-source/source/isaaclab_newton/isaaclab_newton/physics/newton_manager.py) executes registered post-step callbacks after its solver substeps (around lines 1732–1762). The [articulation registration](../target/isaaclab-source/source/isaaclab_newton/isaaclab_newton/assets/articulation/articulation.py) installs `_refresh_user_order_state` when joint/body ordering or ball-joint gathering is needed (around lines 3475–3491). Under identity ordering without ball joints, the Tier-1 arrays are already direct state views. In every role, the producer also explicitly invokes `_refresh_user_order_state` in `force_queries`, so its Warp launches are part of each captured graph when ordering requires them.

For `reset`, the official masked writers update the simulation arrays and invalidate FK; the role then calls `manager.forward()` followed by the explicit user-order refresh. For `context` and `refresh`, `manager.forward()` contains a Python guard: it returns if both `kinematics_dirty` and `transforms_may_change_on_graph_replay` are false (around lines 653–670). During the preceding `reset` capture, masked root/joint writes call `invalidate_fk`, whose `_mark_transforms_changed` sets `transforms_may_change_on_graph_replay=True` while the CUDA stream is capturing (around lines 680–696 and 1061–1083). That flag is not cleared by `forward`; its reset to false is in `NewtonManager.clear()` (around line 853). **Thus the current capture order is material:** it makes the context/refresh `forward` paths enter capture rather than be omitted by the Python guard. A reorder of the four captures needs a fresh audit.

At `dt=0`, Python timestamp guards can skip *derived* Tier-2 cache refreshes during capture. This audit covers only the four Tier-1 exported views; adding a derived getter to the bundle requires a separate capture-safe dataflow proof. The remaining proof gap is a real exported-bundle test: mutate actions, selected reset states and context COM/friction values; launch each saved graph repeatedly through the native runtime; compare the four output views and derived 71-value state against the live SDK at matched steps. In particular, verify unchanged-world masks, post-reset FK, post-context model updates and repeated refresh with no Python activity. The source inspection supports why Tier-1 values should refresh, but it does not prove actual captured kernel contents, output aliasing or numerical equality on GB10.
