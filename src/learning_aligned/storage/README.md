# Bounded native reference storage

The native aligned loaders accept `storage="mmap"`, `cache_dir`, and `max_gather_frames` (default 131072). The native command maps config fields `reference_storage`, `motion_cache_dir` and `max_reference_gather_frames` to those APIs for training, standalone evaluation and held-out automatic evaluation. If no cache path is supplied, it uses `OUTPUT.reference-cache`.

`mmap` is the compatibility config name shared with the Python baseline. This implementation uses **fixed-window POSIX file reads**, not a whole-corpus memory mapping. Each reader owns at most one file descriptor and a 64 KiB read window. C handles are MoonBit external objects with finalizers. Returned state arrays are owned copies, and body FK is computed only for selected frames.

Source CSV is read in 64 KiB byte chunks with an incremental SHA256. Lines are bounded to 64 KiB; longer lines fail explicitly. Only one raw row, the byte carry and three resampled poses are needed during conversion. Raw 36-value Float64 rows go to a temporary disk file; 50 Hz interpolation and central/endpoint derivatives use the same MoonBit formulas as eager storage and emit 76-value little-endian Float64 state rows. No raw-clip or full-corpus frame array is retained.

Each persistent shard is keyed by source SHA256, source FPS and `moonrobo.motion-shard.f64le.v1`. The version must change if cache layout or interpolation/derivative semantics change. Metadata records source hash, FPS, source/resampled frame counts and the complete state-file hash. Reopening verifies current source bytes and cached output bytes. A corrupt/truncated binary is rebuilt; source tampering is rejected. Per-shard file locks serialize writers. Binary and metadata are published by rename after completed, synced writes; unfinished `.partial` files are reconstructed after interruption. Existing completed shards are reused, so a cancelled catalog build resumes at clip granularity.

Clip boundaries, clip IDs/names/hashes, parsed manifest and one-second bins remain in memory. Per-frame clip/bin IDs are binary-search calculations, and full reference body arrays are not stored. `FrameStore.gather` rejects batches exceeding `max_gather_frames`; bulk `map` and preview lengths also enforce the cap. Scalar indexing preserves existing learner, environment, evaluator and exporter callsites. `all` streams values without building a full output. Eager mode preserves its previous array semantics through the same wrapper.

Native cache readers assume completed cache files remain immutable while a library is in use. Unexpected read failure is fatal, with no zero/stale-reference fallback. Different processes may use a shared cache, but external deletion or in-place edits during training are unsupported. Separate readers are required for concurrent calls from multiple OS threads; the current native learner is synchronous.

Storage is 608 bytes per resampled frame on disk, plus transient 288 bytes per source frame for the one clip being converted. Disk write exhaustion fails explicitly. OS filesystem page cache is reclaimable kernel memory; the fixed window bounds owned user-space reference buffers, not total system cache or learner/autodiff allocations. This is not a measured full training memory guarantee.

`load_motion_manifest`, `load_motion_directory`, and `load_motion_files` also accept `motion_cache_advice=true` for an explicit Linux-only page-cache hint during streamed loading. The default is `false`, retaining the original IO path. With this option, each source CSV and persistent Float64 shard is read in at most 64 KiB chunks through one native file descriptor. Source bytes must match the manifest SHA256 before a hint; reused shard bytes must match the metadata SHA256. A newly generated shard is fully reread and hashed before its digest is published in metadata and the hint is issued. On Linux, `posix_fadvise(fd, 0, size, POSIX_FADV_DONTNEED)` applies to that same verified descriptor; it never unlinks a source/cache file or drops global caches. The new descriptor rejects symlinks and non-regular files. This avoids advising an unrelated file substituted at the pathname between verification and advice, but cannot prevent in-place writes to the same inode by another process. Completed cache files must remain immutable.

The optional `cache_advice_report=Some(callback)` receives cumulative counters after the first clip of a catalog larger than 1000 clips, every 1000 completed clips, and at the final clip when advice is enabled. `source_verified_*` and `shard_verified_*` count SHA-matching inputs; `new_shard_hashed_*` counts freshly written shards whose full digest was computed for metadata, not a comparison with a pre-existing expected digest. `advised_*` records successful hints over byte ranges `[0, file_size)`; `unsupported_files` reports non-Linux platforms, and `failed_files` records rejected hints. `last_advice_error` carries the latest unsupported/failure message. These counters describe requests, not actual pages reclaimed. Errors during IO or SHA checks, including a detectable file-size/type change between hash and hint, remain fatal. An unsuccessful or unavailable cache hint does not override the existing memory guard or change motion/shard identity, and should be reviewed from the report before a memory-constrained launch.

Small native tests execute genuine C file IO and compare every state/FK/goal/clip/bin with the eager implementation, including 120→50 Hz interpolation, 64 KiB input/window crossings, short clips, final-frame bins, comments/CRLF/no final newline, cache reuse, corrupted binary regeneration, source hash rejection and gather-cap rejection. The full BONES corpus and GPU paths have not been executed. The aligned learner still uses CPU Float64 reverse-mode AD; this storage addition does not integrate the optional CUDA tensor backend or NCCL training.
