# Temporal and balance Python migration

This is a parallel implementation. All original Python files remain unchanged. No Python subprocess is used by these packages. Matching the assigned filename patterns found **38 source files: 26 providers and 12 tests**.

Only lightweight `moon check` has been run. Tests, training, physics experiments, throughput measurements, parity comparisons and historical checkpoint comparisons are deferred. A successful check is not evidence that a scientific result has been reproduced.

## Implemented entry points

- `moon run src/learning_temporal/cli -- initialize actor.json config.json temporal.json`
- `moon run src/learning_temporal/cli -- initialize-value temporal.json dynamics.json config.json value.json`
- `moon run src/learning_temporal/cli -- fit-actor temporal.json training-points.json config.json output.json`
- `moon run src/learning_temporal/cli -- fit-value value.json value-points.json config.json output.json`
- `moon run src/learning_temporal/physics/cli -- libmujoco scene.xml actor.json value.json physics-config.json output-prefix`
- `moon run src/learning_balance/cli -- learned training-points.json output.json`
- `moon run src/learning_balance/cli -- sustained training-points.json output.json`
- `moon run src/learning_balance/cli -- export-evaluations evaluation.jsonl.gz expected-storage-sha256 output.json`
- `moon run src/learning_balance/cli -- export-npz training-points.json output.npz`

These commands are documented, **not executed**. Point-file schema and configuration are the public `FromJson` record types in `runner.mbt`, `training.mbt`, `artifacts.mbt`, and `physics/runner.mbt`. JSON point readers accept gzip. Native physics uses the explicitly supplied shared library and scene. The PPO driver collects actual simulator transitions, preserves latent Gaussian samples, validates offline/online causal histories, uses finite physical returns, clips the PPO objective, checks full-batch KL after every actor step, fits the value network, selects on validation physics, and writes best/latest paired checkpoints plus held-out test reports. Incoming value checkpoints must be calibrated and paired to the exact actor SHA256.

## Numerical and artifact differences requiring later comparison

The detailed method-level test-source mapping, authored assertions, external
MuJoCo/G1 requirements and precise collector boundary are documented in
[`../learning_balance/TEST_MIGRATION.md`](../learning_balance/TEST_MIGRATION.md).
Test execution remains deferred by the user; no passing runtime test or parity
result is claimed.

- Training and loaded neural networks currently use float64; original training/inference mixes float32 and float64. `learning_balance/float32` supplies a distinct operator-rounded Float32 route for geometry, frame transport, causal observers and fixed feedback, including original dtype-specific geometry thresholds. Reduction order/transcendental-library parity remains untested.
- Learned-head OLS now calls the independent `vectie/moonnum/linalg` column-pivoted Householder QR with a full-rank requirement. The previous twice-reorthogonalized modified Gram-Schmidt source and SHA are preserved in `docs/migration-baselines/shared-numerics/learning-numeric-before-moonnum.json`. Python uses LAPACK `gelsd` SVD. Neither the shared QR's diagonal condition estimate nor its rank-deficient basic solution is an SVD condition number/minimum-norm solution; this remains a scientific parity gap. Checkpoint array order is unchanged, while reduction order and rank decisions require later comparison.
- MoonBit RNG is xorshift32/Box-Muller, distinct from Torch and NumPy. Saved seeds alone do not establish sample equivalence.
- New checkpoints use `moonrobo.moonbit-checkpoint.v1` JSON. Restricted structural Torch ZIP/pickle import is provided without Python; temporal/base/value and learned-v1/sustained-v2 loaders validate explicit formats, tensor shapes and prefixes. Float64 execution of imported float32 tensors still needs numerical/physical comparison. Parent networks are structurally reconstructed and best/latest states are kept separately.
- Pure head checkpoints preserve head/config/provenance. Complete `learning_balance/policy` bundles embed the temporal parent, kinematics, head, observer cadence/window and provenance; head-only CLI outputs remain distinct from these complete actor artifacts.
- Native calls require the matching MuJoCo library and model. New native PPO outputs record actual transitions and leave `parity_verified=false` and `physical_execution_allowed=false`.
